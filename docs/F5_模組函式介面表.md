# F5 模組函式介面表（Module Interface）

模組檔：`src/f5_filter.py`　負責人：組員（ouyue0805）　版本：v1.1
依賴：`src/common/result.py`、`src/common/validators.py`、`src/common/periods.py`、`src/f1_data.py`、`src/f2_enrollment.py`。
所有對外公開函式皆回傳 `{ok, data, errors}`，不主動拋出例外；輸入驗證失敗時 `data` 為 `None`，條件矛盾時 `data` 仍保留候選與排除清單供調用端呈現。

---

## 1. 對外核心函式

| 函式 | 輸入 | 處理流程 | `data` 結構 | 錯誤碼與 detail |
| :--- | :--- | :--- | :--- | :--- |
| `filter_courses(state, criteria)` | `state`：全域狀態<br>`criteria`：個人條件 dict | 1. **前置輸入驗證**（`_validate_criteria`）：<br>　- 檢查 criteria 是否為 dict。<br>　- 檢查 student_id 存在與合法性。<br>　- 檢查學分上下限是否為非負整數。<br>　- 檢查清單欄位型態。<br>　- 檢查星期範圍（1～7）與時段格式。<br>　- 檢查課號存在性及必修是否已取消。<br>　- 失敗直接中斷回傳 `data=None`。<br>2. **基本過濾與排序**（`_split_courses`）：<br>　- 依 F2 選課規則與不可上課時段產生候選與排除清單。<br>　- 候選排序：希望課程 $\to$ 偏好星期 $\to$ 課號字典序。<br>　- 排除清單依課號排序，原因依字母排序。<br>3. **條件矛盾檢查**（`_contradiction_errors`）：<br>　- 檢查六種 CONSTRAINT_CONTRADICTION。<br>　- 檢查獨立錯誤碼 MIN_CREDIT_UNREACHABLE。<br>4. **判定可行性**：<br>　- 無任何矛盾時 `feasible=True, ok=True`。<br>　- 存在矛盾時 `feasible=False, ok=False`，但保留候選與排除資料。 | **驗證成功時**：<br>`{`<br>　`"student_id": str,`<br>　`"candidates": list[dict],`<br>　`"excluded": list[dict],`<br>　`"feasible": bool`<br>`}`<br><br>**驗證失敗時**：<br>`None` | **輸入驗證錯誤**：<br>- `INVALID_FIELD`（`{"field": ...}`）<br>- `NOT_FOUND`（`{"kind": "student"/"course", ...}`）<br>- `INVALID_PERIOD`（`{"day": ...}` 或 `{"slot": ...}`）<br>- `INVALID_CREDIT`（`{"field": ..., "value": ...}`）<br>- `COURSE_CANCELLED`（`{"course_id": ...}`）<br><br>**條件矛盾錯誤**：<br>- `CONSTRAINT_CONTRADICTION`（`{"reason": ...}`）<br>- `MIN_CREDIT_UNREACHABLE`（`{"min_credits": ..., "max_reachable": ...}`） |

## 2. 輸入條件規範（`criteria` Schema）

| 欄位名稱 | 型態 | 必要性 | 預設值 | 合法值限制與說明 |
| :--- | :--- | :---: | :---: | :--- |
| `student_id` | `str` | **必填** | — | 須存在於 `state.students` 中，否則回報 `INVALID_FIELD` 或 `NOT_FOUND`。 |
| `min_credits` | `int` | 選填 | `0` | 非 bool 整數且 $\ge 0$；若為字串、負數回報 `INVALID_CREDIT`。 |
| `max_credits` | `int` | 選填 | 學生上限 | 非 bool 整數且 $\ge 0$；運算時取 `min(criteria.max_credits, student.credit_limit)`。 |
| `wanted_courses` | `list[str]` | 選填 | `[]` | 課號清單；課號須存在於 `state.courses`，否則回報 `NOT_FOUND`。 |
| `required_courses` | `list[str]` | 選填 | `[]` | 課號清單；課號須存在於 `state.courses`（不存在回報 `NOT_FOUND`），且課程不可為 cancelled（否則回報 `COURSE_CANCELLED`）。 |
| `preferred_days` | `list[int]` | 選填 | `[]` | 偏好星期；元素須為 1～7 之整數，若超出範圍回報 `INVALID_PERIOD`。 |
| `blocked_slots` | `list[dict]` | 選填 | `[]` | 不可上課時段；元素須符合 `{"day": 1~7, "period": "1"~"9"/"a"~"c"}`，格式不符回報 `INVALID_PERIOD`。 |

## 3. 輸出資料詳細規格

### 候選清單（`candidates`）單一項目結構
```json
{
  "course_id": "1150001",
  "name": "演算法",
  "credits": 3,
  "wanted": true,
  "preferred_day": true
}
```
- **排序依據**：
  1. `wanted` 為 `True` 者優先於 `False`。
  2. `preferred_day` 為 `True` 者（該課程所有時段皆落在 `preferred_days`）優先於 `False`。
  3. 課號字典序（遞增）。

### 排除清單（`excluded`）單一項目結構
```json
{
  "course_id": "1150002",
  "reasons": ["ALREADY_ENROLLED", "BLOCKED_SLOT"]
}
```
- **排除原因代碼（依字母排序）**：
  - `ALREADY_ENROLLED`：學生已選修此課程。
  - `CANCELLED`：課程狀態已取消。
  - `CONFLICT_ENROLLED`：課程時段與學生已選課程衝堂。
  - `FULL`：課程選課人數已達容量上限。
  - `BLOCKED_SLOT`：課程時段與個人不可上課時段重疊。

## 4. 錯誤代碼與 Detail 規格表

| 錯誤碼 (`code`) | 中文說明 (`message`) | `detail` 鍵值 | 說明 |
| :--- | :--- | :--- | :--- |
| `INVALID_FIELD` | 欄位缺漏或不合法 | `{"field": "criteria" / "student_id" / ...}` | criteria 非 dict、缺少 student_id、或清單欄位非 list 型態 |
| `NOT_FOUND` | 找不到資料 | `{"kind": "student", "student_id": "..."}`<br>`{"kind": "course", "course_id": "..."}` | 指定之學號不存在，或必修/希望課程代號不存在 |
| `INVALID_PERIOD` | 星期或節次不合法 | `{"day": int}`<br>`{"slot": dict}` | preferred_days 星期超出 1~7，或 blocked_slots 格式不合法 |
| `INVALID_CREDIT` | 學分數值必須為非負整數 | `{"field": "min_credits"/"max_credits", "value": ...}` | 學分上下限非整數、型態為 bool 或數值小於 0 |
| `COURSE_CANCELLED` | 必修課程已取消 | `{"course_id": "..."}` | `required_courses` 指定之課程狀態為 `cancelled` |
| `CONSTRAINT_CONTRADICTION` | 條件互相矛盾 | `{"reason": "MIN_GT_MAX", "min_credits": int, "max_credits": int}` | 學分下限大於有效上限（max_credits 與學生 credit_limit 之較小者） |
| `CONSTRAINT_CONTRADICTION` | 條件互相矛盾 | `{"reason": "REQUIRED_CONFLICT", "course_id": str, "with_id": str}` | 兩門待選必修時段互相衝堂（每對僅列一筆，課號較小者在前） |
| `CONSTRAINT_CONTRADICTION` | 條件互相矛盾 | `{"reason": "REQUIRED_ENROLLED_CONFLICT", "course_id": str}` | 待選必修與學生目前已選課程衝堂 |
| `CONSTRAINT_CONTRADICTION` | 條件互相矛盾 | `{"reason": "REQUIRED_BLOCKED", "course_id": str}` | 待選必修時段落在個人不可上課時段（blocked_slots） |
| `CONSTRAINT_CONTRADICTION` | 條件互相矛盾 | `{"reason": "REQUIRED_FULL", "course_id": str}` | 待選必修課程名額已額滿 |
| `CONSTRAINT_CONTRADICTION` | 條件互相矛盾 | `{"reason": "REQUIRED_OVER_MAX", "total_credits": int, "max_credits": int}` | 目前已選學分加待選必修學分總和超過有效上限 |
| `MIN_CREDIT_UNREACHABLE` | 可選學分不足以達到學分下限 | `{"min_credits": int, "max_reachable": int}` | 目前已選學分加全部候選課程學分總和依然小於 min_credits |

## 5. 模組內部私有函式說明

| 函式名稱 | 責任說明 |
| :--- | :--- |
| `_validate_criteria(state, criteria)` | 集中處理 criteria 各欄位型態、範圍、存在性與合法性，防止程式當機。 |
| `_split_courses(state, student_id, criteria)` | 遍歷系統課程，透過 `_exclusion_reasons` 分流出候選與排除清單並完成排序。 |
| `_exclusion_reasons(state, student_id, course_id, blocked_slots)` | 整合 F2 `check_enrollment` 與不可上課時段比對，產出單門課的排除原因清單。 |
| `_candidate_row(course, wanted, preferred_days)` | 將合格課程轉換為候選項目 dict，標註 `wanted` 與 `preferred_day` 標籤。 |
| `_rank_key(row)` | 候選排序 key：優先比對 `not wanted`，其次 `not preferred_day`，最後 `course_id`。 |
| `_effective_max(state, student_id, criteria)` | 計算有效學分上限：取 criteria 傳入值與學生本身 credit_limit 兩者之最小值。 |
| `_pending_required(state, student_id, criteria)` | 取得必修中尚未選修且未被取消的有效課號清單（依課號遞增排序）。 |
| `_contradiction_errors(state, student_id, criteria, candidates)` | 整合呼叫六種矛盾檢查函式與學分不足檢查函式，固定順序產出錯誤清單。 |
| `_min_credit_unreachable_errors(state, student_id, candidates, min_credits, max_credits)` | 僅在 $min \le max$ 時計算可用學分上限是否低於 $min$，回報獨立錯誤碼。 |
